Your device creates a request

Your browser prepares a request for the website. The data is split into network packets and sent using the network stack.

What actually happens?

Three ideas explain most of the journey.

▤

Packets

Information is divided into smaller units. Each packet carries addressing and control information so network equipment can move it toward its destination.

↗

Routing

Routers examine destination IP addresses and forwarding tables to choose the next hop. A route can cross many independent networks.

🔒

HTTPS

For secure websites, TLS helps protect data in transit and verifies the server's identity. Encryption is not the same thing as anonymity.

Component details

Your device

Your laptop or phone runs the browser and creates requests. It uses a network interface and usually receives its local IP configuration from the router through DHCP.

Think of this as the starting point: your browser asks for a resource, such as a web page.

Local network vs. internet

They are connected, but they are not the same thing.

Local area network (LAN)

Your phone, laptop, printer and router can communicate within a local network. Private IPv4 addresses are commonly used here, and the router often acts as the default gateway.

Nearby devices · Local addressing

Wide area network (WAN)

The internet connects many networks around the world. Your traffic can pass through your provider and multiple routers before reaching a remote server.

Interconnected networks · Routing

Four core stages

A simplified mental model of browser networking.

01 · Resolve

DNS lookup

The browser or operating system needs an IP address for the domain. A cached answer may skip a fresh lookup.

02 · Connect

Transport + security

Depending on the protocol, the client establishes the necessary transport connection and security session. Modern HTTP/3 uses QUIC over UDP.

03 · Request

Ask for a resource

The browser sends a request for a page, script, image, or other resource.

Name resolution

DNS: the internet's address book.

People remember names; computers send traffic to IP addresses. DNS helps connect the two.

Resolution flow

From name to address

A simplified recursive lookup, assuming a usable cached answer is not already available.

01
Browser / device cache

Check whether a recent answer is already known.

02
Recursive resolver

The configured resolver looks for an answer on the client's behalf.

03
Root and domain servers

If needed, DNS referrals guide the resolver toward the correct authoritative servers.

04
Authoritative answer

The resolver obtains a record, caches it according to its TTL, and returns the answer.

What to use for deeper diagnostics

Ping

Tests reachability and round-trip time using ICMP where allowed. Some hosts block it, so no reply does not always mean the host is down.

Traceroute

Shows responding hops along a route where network devices permit it. Paths can vary and some hops may not respond.

DNS tools

Tools such as nslookup or dig query DNS and help inspect returned records, TTLs and resolver behavior.

Quick reference

Network glossary.

Short, plain-English definitions for the building blocks used throughout this lab.

IP address

A logical address used to identify a network interface for IP communication.

Router

A device that forwards IP packets between networks based on routing information.

DNS

The Domain Name System translates names into records, including IP addresses.

Packet

A formatted unit of data carried by a network-layer protocol such as IP.

TCP

A transport protocol that provides a reliable, ordered byte stream.

UDP

A lightweight transport protocol without TCP's built-in delivery guarantees.

HTTPS

HTTP protected by TLS, which helps provide encryption and server authentication.

Latency

The time it takes for data to travel through a system; round-trip time measures a trip there and back.

Bandwidth

The capacity of a link to carry data over time, often measured in bits per second.

Default gateway

The router a device typically sends traffic to when the destination is outside its local subnet.

MAC address

A link-layer address used to deliver frames on a local network segment.

ISP

An Internet Service Provider that supplies connectivity to other networks.
